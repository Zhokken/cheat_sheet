Git & GitHub – trygg arbeidsflyt
Inspirasjon

FAST ARBEIDSFLYT

PULL → JOBB → SJEKK → COMMIT → PUSH → SJEKK

1. START

  • Åpne riktig prosjektmappe i VS Code.
  • Kontroller at du er på riktig branch, vanligvis main.
  • Kontroller at riktig Git-repository er koblet til.
  • Hent siste endringer fra GitHub før du begynner å jobbe.

2. JOBB

  • Lag eller endre filer i VS Code.
  • Arbeid lokalt på PC-en.
  • Sjekk status underveis for å se hvilke filer som er endret.

3. KONTROLLER

  • Se hvilke filer som er endret.
  • Kontroller hva som faktisk er lagt til, fjernet eller endret.
  • Rett eventuelle feil før du lagrer endringene i Git-historikken.

4. COMMIT

  • Velg hvilke endringer som skal lagres.
  • Lag en commit med en kort og beskrivende melding.
  • Lag flere små commits i stedet for én stor commit etter flere dager.

Gode commit-meldinger:

  • Lag navigasjonsmeny
  • Rett feil i mobilmeny
  • egg til validering

Dårlige commit-meldinger:

  • test
  • ting
  • oppdatering
  • asdf

5. PUSH

  • Hent eventuelle nye endringer før du pusher når du samarbeider eller bruker flere PC-er..
  • Send commitene til GitHub.
  • Kontroller på GitHub at filene og siste commit ligger der.
  • Kontroller at du ser på riktig branch.

GitHub

GitHub er en skybasert nettside og plattform der utviklere lagrer, deler og samarbeider om programvare

Git Bash

Git Bash er et program for Windows som gir deg en ledetekst (terminal) med støtte for både Git-kommander og Unix-likende kommandoer

Basic Git commands

git init — Initialiserer et nytt Git-repositorium.
git add . — Gjør alle endringer klare for neste commit.
git commit -m "Initial commit" — Lagrer endringene med en beskrivende melding.
git push — Laster opp commitene dine til et eksternt repositorium.


GIT i VS-Code

det er mer intuitivt å bare klikke i vscode, som du kan se på vedlagt bilde ovenfor. (Bare commit rett der..) enn det er å bruke git Bash som du kan se nedenfor.

Hva er en .md fil?
